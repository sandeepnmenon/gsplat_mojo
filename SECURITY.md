# Security policy

## Supported versions

No stable release is currently supported.

| Version | Status |
|---|---|
| Unreleased `0.1.0a0` candidate / default branch | **Best effort — Tier 2** security review and fixes |
| Stable releases | **Planned**; none exist |

The **Tier 2** label means reports are triaged as maintainer capacity permits;
it is not an SLA or a statement that the code has completed a security audit.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion,
or pull request. The repository does not yet document a verified private
security-reporting channel. Ask a repository maintainer through their GitHub
profile for a private route without including vulnerability details.

Configuring and testing a durable private intake channel—preferably GitHub
private vulnerability reporting—and publishing expected acknowledgement and
remediation windows is a release policy blocker.

When a private channel is available, include the affected revision, environment,
impact, reproduction steps or proof of concept, and any suggested mitigation.
Avoid accessing data or systems you do not own.

## Disclosure

The maintainers will coordinate a disclosure date after assessing a report.
No timeline is promised before the private intake and response policy are
configured. Security fixes and advisories will identify affected versions when
releases exist.
